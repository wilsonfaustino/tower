# Tower MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS menu bar app that shows the GitHub PRs and Jira tickets that need the owner now, in the sections Fix, Review, Merge, Tidy.

**Architecture:** `Core` framework holds models, clients and the queue rules as pure, unit-tested code. The `Tower` app target holds one `@Observable` store, the `Theme` enum and the SwiftUI views. Clients get an injected transport, so no test calls the network.

**Tech Stack:** Swift 6, SwiftUI `MenuBarExtra(.window)`, Swift Testing, XcodeGen, Xcode 27.1, macOS 26 target. No third-party dependencies.

**Spec:** `docs/superpowers/specs/2026-11-05-tower-mvp-design.md`. Design detail: Serena memories `design/tokens`, `design/components`, `design/panel-states`, `design/icons`.

## Global Constraints

- macOS 26.0 deployment target, `SWIFT_VERSION: "6.0"`, strict concurrency on.
- Bundle ID `dev.wilsonfaustino.Tower` (app), `dev.wilsonfaustino.Tower.Core`, `dev.wilsonfaustino.Tower.CoreTests`. Display name "Tower".
- XcodeGen only. Never hand-edit `.pbxproj`. `*.xcodeproj/` is gitignored.
- `Core` imports Foundation and Security only, never SwiftUI or AppKit. `Core` is a framework, so every type and function the app uses is `public`.
- Hardened runtime on, no App Sandbox, `LSUIElement = YES`.
- Panel copy is fixed by the spec. Copy it word for word.
- Descriptive names. Comments only for magic numbers and non-obvious logic. No emojis.
- Stage files by name. Never `git add -A` or `git add .`. New commit per task, never amend.
- Test command for every task: `xcodegen generate && xcodebuild -scheme Tower -destination 'platform=macOS' test -quiet`.

## Review Focus

1. A PR that is both failing and approved: it must show in Fix only, not in Merge. Test in Task 3.
2. Ticket key `PROJ-14` against a branch `proj-143-export`: no match (whole-token, case-insensitive). Test in Task 3.
3. `gh` installed but logged out (`gh auth token` exits non-zero, empty stdout): auth failure, not network failure, so the banner shows and the offline screen does not. Test in Task 5.
4. A cache file that does not decode (old format, partial write): treat as no cache, never crash. Test in Task 7.
5. Jira not configured (no site URL or token): Tidy is empty, no banner, no offline screen. Jira counts as "not configured", not as a failure. Test in Task 6 and Task 7.

### Task 3: Queue rules

**Files:**
- Create: `Core/TicketKeyMatcher.swift`, `Core/QueueBuilder.swift`, `CoreTests/TicketKeyMatcherTests.swift`, `CoreTests/QueueBuilderTests.swift`

**Interfaces:**
- Consumes: Task 2 models, `shortAge`.
- Produces:
  - `func ticketKey(_ key: String, matches text: String) -> Bool`
  - `struct QueueInput { viewerLogin: String; authoredPullRequests: [PullRequest]; reviewRequests: [PullRequest]; jiraTickets: [JiraTicket] }`
  - `func buildQueue(_ input: QueueInput, now: Date) -> [QueueSection]` (non-empty sections only, in `SectionKind` order, items oldest `sortDate` first)

Rules (from the spec table): Fix = authored, not draft, `checkState` in [failure, error], badge `"\(failedCheckCount) checks failed"` (use `"1 check failed"` for one). Merge = authored, `approved`, `checkState` not failure/error. Review = reviewRequests; `sortDate = reviewRequestedAt ?? updatedAt`; older than 24 h -> `"Waiting \(days)d"` urgent, else `"+\(additions) −\(deletions)"` neutral (U+2212 minus). Tidy = each ticket: no authored PR whose title or `headBranch` matches -> "No PR"; matched PR with empty `requestedReviewerLogins`, empty `requestedTeamSlugs` and `reviewCount == 0` -> "No reviewer"; else no row. Meta lines and team label exactly as in the spec "Meta line" section; team = first `requestedTeamSlugs` entry when `viewerLogin` is not in `requestedReviewerLogins`.

- [ ] **Step 1:** Matcher tests: `PROJ-14` in `"PROJ-14 add export"` true; in `"feature/proj-14-export"` true; in `"proj-143-export"` false; in `"XPROJ-14"` false.
- [ ] **Step 2:** QueueBuilder tests, one per rule: failing PR in Fix with `"3 checks failed"`; failing and approved PR in Fix only (Review Focus 1); draft failing PR absent; approved green PR in Merge with `"Approved"`; review at 23 h neutral `"+12 −4"`, at 25 h urgent `"Waiting 1d"`; team request meta `"app-web #2179 · Ana · team web-core · 1d"`; ticket with no PR -> `"No PR"`, meta `"PROJ-1432 · In Progress · 3d"`; ticket with matched unreviewed PR -> `"No reviewer"`; ticket with matched reviewed PR absent; empty input -> `[]`; section order Fix, Review, Merge, Tidy.
